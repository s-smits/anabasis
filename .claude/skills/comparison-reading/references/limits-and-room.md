# Rejections, the budget, room, patience, and promotion

Read this reference for Referee rulings, solve budgets, improvement headroom, stopping patience,
task review, and promotion (`AGENTS.md` section 7).

## Rejections

A verifier rejection counts as a failure only once the Referee rules it `earned` on the basis of an
answer probe that changes a refusing check's outcome (`src/audit/auditor.ts`). Otherwise the task
is set aside until human labels settle it (`settle.ts`). If more than 3 tasks incur a check defect
or an unrunnable check (`--defects`), the comparison halts because the check program requires
inspection before spending further budget.

## The budget

The binding compute limits are the solver's model turns (`--solve-model-turns`, reported in tool
results; exhausting them without submitting yields `turns-ended`) and the wall-clock deadline
(`--solve-minutes`). Both the prompt turn limit (`LIMITS.turns`) and the per-command timeout are
identical across all solves. Always interpret a comparison under the budget at which it ran:
applying a tighter budget post hoc still reflects trajectories generated by a solver that knew the
larger budget.

## The dollar cap

A solve is not launched if reserving its estimated cost alongside every solve currently in flight
would exceed `--cap`.

## Room for improvement

`roomOf` (`src/kernel/reports.ts`) classifies the pool as **room** when at least one task is
informative for the reference (`informative`), **too-hard** when no valid answer exists on record
for any task, and **none** otherwise. Because the superior answer may belong to the reference, the
candidate, or the task author, headroom can arise from either validity or the declared objective.

## Improvement patience

`stopRule` (`src/campaign/admission.ts`) counts eligible moves since the last promotion. A move is
eligible when a Builder session's modified harness was evaluated against the reference in a
comparison that tallied at least one task and left room, or when a session left the harness
unchanged despite a failing practice solve. Starter comparisons and comparisons that scored no tasks
or found no room do not increment the counter, and the stop rule never terminates a campaign that
has earned a promotion since the counted streak.

## Awaiting task review

A task that receives no valid answer across two comparisons enters task review, unless a valid
answer already exists on record (`task.feasible`: from a prior solve, an author answer verified
under its task identifier, or a stored pack answer passing at `prepare`) or its solves were
truncated by a deadline or context window (`poolOf`). Exhausting all model turns does not count as
truncation because turns are the explicit budget, except when context exhaustion or a provider error
terminated the final turn (`windowEnded`, `providerFailed`).

## Promotion

A comparison invoked without `--reference` evaluates against the most recently promoted harness;
passing an explicit `--reference` digest evaluates without triggering promotion.
