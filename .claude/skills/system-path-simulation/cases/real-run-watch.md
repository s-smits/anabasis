# Watch a real run as the condition

**Use this case when:** the question is whether a fresh project on a new head reaches its first
preview, clears the gate and hands over to the Built Harness (Builder → gate → Built), and no
recorded position stands before that path. A seeded round copies a campaign that has already
passed it; the real `fullrun` from the one-liner is the smallest slice that measures it.

## Procedure

1. **Write the prediction file before launch:** the moved variable, the fixed slots, and three or
   four rows a recorded file can refute (first preview within N minutes; no refusal row routed to
   the wrong owner; adoption within N hours; one row per fault). Scout each row to the file that
   will hold it (SKILL.md, "Scout every prediction to its bytes").
2. **Check the allowance, not only the login.** A Claude session limit ends the run in the
   Builder's first turn as `environment-blocked` (three minutes on 2026-09-15), and a fresh token on
   the same account shares the window. The launcher's probe runs one minimal Builder-slot turn and
   refuses with the provider's reset clause; read that clause and start the launcher after it.
3. **Launch through `launch-run`** on the resolved stack head. Nothing else changes: the preset's
   one-liner, no context files, no extra flags.
4. **Watch through recorded bytes**, not the log alone:
   - `fullrun.log` lines naming `correctness_check`, `submit`, a refusal, adoption, a battery, a
     terminal or `[safeguard]`;
   - the iteration feedback rows for the owner and code of every refusal, under the campaign's
     `controller/<run>/` tree;
   - `scripts/difficulty-watch.mts` for the authoring sequence and submit rows, codes only;
   - `bun run outcome <campaignDir> --builder` during a quiet Builder turn.
   Resolve no row from Builder prose or protected verifier output.
5. **Resolve** each row `sufficed`, `partial`, `refuted` or `untriggered` against the file it was
   scouted to, and give each refuted row one owner: setup, shared product code, generated
   candidate, or provider and host environment.
6. **Stop only under `whole-run-investigation`'s outcome reference** and the stop section of `launch-run`. A provider
   non-result is not a product finding; relaunch after the allowance resets.

## What it proves

A verified case proves the whole path once; a refusal row proves that owner's gate; an
`environment-blocked` terminal proves nothing about the product. Report the run id, source,
project and the prediction file's digest beside the resolutions.
