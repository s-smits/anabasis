# Mutation Testing

Mechanical mutation oracle for high-importance Anabasis owners (`AGENTS.md` §12). Pairs syntactic mutations (`scripts/mutate.ts`) and incremental nightly sweeps (`scripts/nightly.ts`) with a four-stage triage funnel so test coverage rises on real invariants without example-test bloat.

Tightly linked to [`simplify`](../simplify/SKILL.md) (delete or simplify redundant/low-value production code before adding tests), [`commit-r`](../commit-r/SKILL.md) (which invokes this oracle at step 8 whenever rewriting or replacing tests on high-importance owners), [`reduce-complexity`](../reduce-complexity/SKILL.md), and [`local-checks`](../local-checks/SKILL.md).

## Commands

```sh
bun .claude/skills/mutation-testing/scripts/mutate.ts list <copy> <files...>
bun .claude/skills/mutation-testing/scripts/mutate.ts run <copy> <files...> --out <scratch>/kills.jsonl --suites <suites.json> [--fleet] --stop-at-kill --timeout 120
bun .claude/skills/mutation-testing/scripts/mutate.ts report <scratch>/kills.jsonl [--old old] [--survivors]
bun .claude/skills/mutation-testing/scripts/nightly.ts <tree> --state <dir> [--until HH:MM] [--timeout s] [--diff <base>] [--full]
```

## Four-stage survivor triage funnel (nightly & hardening passes)

Never chase raw survivor counts with one example test per mutant. Work in order, drawing on proven industrial mutation practice (Petrović & Ivanković / Google ICSE 2018 & TSE 2021; Meta ACH FSE 2025; Just et al. FSE 2014):

1. **Verify suite coverage first (separate measurement artefacts from real gaps).**
   `nightly.ts` selects tests via `tools/runtime/gate.ts`'s `within` primitive (`NEAR.root = 1` in diff mode with transitive fallback only when no direct test exists; full runtime-transitive imports in `--full` mode, dropping `import type` and `export type` edges) plus non-import string-literal path mentions, ordered fastest-first by `test/.test-timings.json` (then file size) and executed as one bailing `bun test --bail` batch per mutant. When triaging an older pass whose suite list missed transitive importers, confirm survivors against the missed suites first (`--only <ids> --stop-at-kill`) before editing tests. Prioritise **diff-scoped / new survivors** (`report.md` against `done.json`, or `git diff --name-only <base> -- src tools`) over historical sweeps to keep signal high and avoid alert fatigue.
2. **Cluster confirmed survivors by subsuming invariant — simplify or delete production code before adding tests.**
   Inspect each surviving expression inside its full enclosing function and callers (Meta ACH showed deterministic context pre-processing lifts equivalent-mutant filtering from 0.79/0.47 to 0.95/0.96 precision/recall), and inspect any existing test covering that function first. Never blindly append tests to make a survivor go away: first ask *why* the branch wasn't covered — often the production code is redundant, over-defensive, or not important enough to keep. Classify each cluster in order:
   - **Live defect or inert test** (production code wrong today, or an existing test whose fixture accidentally bypasses the branch it claims to pin): fix the owning code or existing test directly rather than adding a duplicate.
   - **Unneeded or over-defensive production surface** (dead guard, duplicate loop/lookup, unreachable fallback, or incidental branch that wasn't covered because no caller relies on it): delete or simplify the production code via [`simplify`](../simplify/SKILL.md) (or [`commit-r`](../commit-r/SKILL.md) for a compartment cut) rather than adding a test to protect code that should not be there.
   - **Unpinned high-importance invariant** (code truly load-bearing on measurement, Factor 1–4 folds, Rule 3 walls, `decide`/admission/stop rules, security boundaries, or refusals): target the **subsuming invariant** for the cluster and close it through the live end-to-end entry point with **one** compact space, table, or property check in the owning suite (`AGENTS.md` §12). Prefer end-to-end / space checks over isolated unit tests; add a narrow unit or boundary test only where exercising the invariant end-to-end is genuinely infeasible.
   - **Arid, low-importance, or presentation surface** (Google's arid-node principle: logging calls—suppressed directly in `mutate.ts`—plus prose formatting, CLI output, advisory notes, or incidental low-value branches): write **no** test ([`commit-r/references/testing-protocol.md`](../commit-r/references/testing-protocol.md)).
   - **Proved equivalent mutant** (identical observable behaviour on all reachable inputs): retire with a one-line proof in the PR/commit body and write **no** test. Common deterministic equivalence classes here:
     - strict vs non-strict comparison (`<` vs `<=`, `>` vs `>=`) between distinct log event kinds that can never share an index;
     - negative-sentinel shifts (`-1 -> -2`) compared against non-negative array or log indices;
     - redundant defensive guards already guaranteed by an earlier invariant or callee (`isContextOverflow`, empty-set no-ops, unreachable `null` fallbacks);
     - algebraic/monotonicity equivalences (verify with a quick bounded script when non-obvious).
3. **Prove every kill against the oracle (zero inert tests).**
   Run `mutate.ts run --only <target-ids> --stop-at-kill` against the edited suites (`ANA_CHECK_HOST=here --jobs N` locally for fast targeted checks; `nightly.ts` writes `survivors.diff-<base>.ids.txt` / `survivors.ids.txt` beside `report.md` and clusters survivors by `file:line` sorted by density so multi-mutant unpinned guards surface first). Check **per targeted line** that every mutant you intended to close flips from `survived` to `killed` with zero `unread` rows: a mutant still surviving on a line you just added a test for proves the test is inert (fix the fixture so it actually reaches the branch, or delete the test). Then run `bun fmt`, `bun run typecheck`, `bun run lint -- --strict`, `bun tools/loc/source-policy.ts`, and `bun run simplify -- --gate`.
4. **Track yield and respect oracle limits.**
   Report exact denominators in the commit/PR: survivors read, indirect kills removed, real invariant gaps closed, live defects or inert tests uncovered, equivalents retired, and simplification leads surfaced. Remember that first-order syntactic mutants catch boundary and logic gaps well, but never catch omitted requirements or cross-file semantic defects—pair this skill with [`system-path-simulation`](../system-path-simulation/SKILL.md), Rule 3 perturbation walls, and [`promotion-tuner`](../promotion-tuner/SKILL.md) archive replays.

## Routing non-error survivors to `simplify` and `commit-r`

A surviving mutant that is **not** a bug and **not** worth a new test is often a structural optimisation signal rather than waste. Before retiring a non-error cluster, check whether deleting or restructuring production code beats leaving it behind:

| Non-error survivor pattern | What it signals | Route to |
| --- | --- | --- |
| Redundant defensive guard (`A \|\| B` where `B` already holds whenever `A` holds, or callee already checks `A`) | Unneeded branch or double validation across a seam | [`simplify`](../simplify/SKILL.md) (delete redundant guard; make invariant unrepresentable) |
| Unreachable fallback (`?? default` that never triggers on reachable states) | Dead code or over-wide return type | [`simplify`](../simplify/SKILL.md) (narrow type, remove dead fallback) |
| High arid-mutant density inside a high-importance owner (prose, advisory notes, CLI formatting mixed into decision folds) | Presentation entangled with decision logic | [`commit-r`](../commit-r/SKILL.md) / [`reduce-complexity`](../reduce-complexity/SKILL.md) (split pure decision fold from presentation surface so high-importance owners stay small and high-signal) |
| Surviving `swap rows` in a decision table | Either an unpinned precedence invariant or disjoint rows with hidden coupling | Inspect reachability first; pin precedence if order matters, else simplify |

Never delete a guard solely to raise kill rate—verify reachability across `data/runs/` and callers first (`AGENTS.md` §9, §12). Record confirmed simplification leads alongside retired equivalents so subsequent `simplify` or `commit-r` passes pick them up cleanly.

## Rewrite-time oracle (`commit-r` step 8)

When deleting, shrinking, or replacing tests on a high-importance owner in [`commit-r`](../commit-r/SKILL.md):

- **Comparative mode (`--old`, Test pass or interface-preserving Rewrite):** run `old`, `new`, and `kept` suites on `<copy>` with old tests restored. Classify every `O-` survivor as either a genuine invariant/boundary gap (close with a bounded/property check; never paste back old example boilerplate) or intentionally retired incidental wording/convenience (record in the commit message). **Leaving >15% of `O-` survivors unexplained or any `unread` row halts the pass** (`report --survivors` prints unread IDs after survivors for `--only` reruns).
- **Solo mode (interface-changing Rewrite):** never mix incompatible `old` and `new` suites on one copy. Run `mutate.ts` against `new` + `kept` (`report` without `--old`), inspect `--survivors`, and close surviving decision, wall, or refusal branches.
- **Skip** on pure low-importance amputations; verify surviving boundary tests, `bun run gate`, and real-input oracle/replay instead.

## Mutation rot (high to low risk)

Mutants rot as code, callers, and test fixtures evolve. Check rot risk in order before trusting a zero-survivor result:

- **High — moved code & stale `--only` IDs:** mutant IDs encode `<file>:<byteOffset>:<label>`. Any edit above a recorded survivor shifts byte offsets so saved `survivors*.ids.txt` entries silently match nothing (`mutate.ts` prints a `stale --only IDs` warning on `stderr` when requested IDs miss). Never treat `0 mutants run` on a stale ID list as proof a fix worked—re-run against the current tree and confirm each targeted line flips from `survived` to `killed`.
- **Medium — fixture-blind tests & stale diff baselines:** a test whose fixture omits a relevant input variant (or only exercises a happy path) leaves mutants alive on lines that appear covered, and incremental diff-hunk runs do not re-test unchanged lines when a callee or shared fixture changes. Re-run the whole touched owner (or `--full`) after refactors or fixture rewrites.
- **Low — retired equivalents & arid blocks:** a mutant proved equivalent under an earlier invariant can become observable once that invariant is relaxed; revisit retired equivalents whenever the enclosing owner changes.

## Execution & clone hygiene

- **Host routing & two-stage execution:** `mutate.ts` pairs **Mode-1 In-Process Mutant Schemata** (`mutate-schema.ts`) with a **Mode-2 Unified Fleet Process Pool** (`mutate-pool.ts`, `mutate-exec.ts`, `tools/runs/host-config.ts`). Under `--prune --stop-at-kill` when local execution is available, Mode 1 compiles function-body mutants (excluding chained short-circuit precedence swaps and top-level initialisers) into one in-memory `Bun.plugin` meta-mutant per file, probes pure deterministic suites once in parallel (aborting automatically if the target executes at import time or fails baseline) to capture exact per-`it()` reachability and durations, ranks pure suites by `coveredMutants / baselineMs`, and shards mutants across local cores running only covering `it()` tests fastest-first with a per-mutant watchdog and baseline self-verification on every kill. Remaining undecided mutants and impure/subprocess suites flow into Mode 2 (`checkPlaces` / `fleetPlaces`, `--local <cores>`, `--batch 48`, `--cov-cache`): LCOV (`DA:<line>,0`) runs only on needed non-subprocess suites, local slots pull one mutant at a time at adaptive concurrency (`1` under full load, scaling to `4` in the tail) using parallel APFS copy-on-write clones and symlinked `node_modules`, and remote hosts run one full-machine worker per host (up to 8 isolated in-slot lanes keeping the synced root pristine, copying `src/`, `tools/`, `test/`, `.claude/`, `studies/`, and mutant/suite roots via `cp -cRp` on macOS or `cp -al` hardlinks on Linux while symlinking `node_modules`, `.git`, `packages/`, and other untouched directories), streaming rows back line-by-line while local workers tail-hedge lagging remote mutants. Under `--stop-at-kill`, `nightly.ts` leads with direct 1-hop importers ahead of transitive suites, Mode 2 dynamically ranks active suites by LCOV hit-density + Bayesian kills-per-second, runs the lead suite solo then distinct single-file rest suites in one bailing `bun test --bail` process (re-verifying any combined kill solo and falling back individually on cross-file leakage or timeouts), and bounds hangs per suite (`min(--timeout, max(20 s, 12× baseline + 10 s))`) while recording hangs as `null` (`unread` whenever no suite kills the mutant). Every active suite must pass unmutated on each host before mutating there; a place giving no verdict hands its remaining mutants back and takes no more. Unrun mutants stay unrecorded so rerunning the same command resumes cleanly.
- **Incremental diff-hunk nightly mode & weekly full sweep:** after an initial complete `OWNERS` pass writes `done.json`, `nightly.ts` defaults to **diff-hunk mode** (`git diff --unified=0` via `changedLinesInDiff` in `src/meta/git.ts`): it mutates only mutants whose start line falls on a changed line across every modified production file under `src/` and `tools/` since the previous complete pass (falling back to `merge-base(origin/main, HEAD)` when the stored commit is no longer an ancestor after a rebase or new stack, or using `--diff <base>` verbatim; pure-deletion hunks produce no mutants), writing `<slug>.diff-<base>.jsonl` using `gate.ts`'s `NEAR.root` (`depth = 1`) fastest-first suites plus joined path/directory mentions batched into one `bun test --bail` call per mutant (falling back to transitive importers only when no direct test exists). `--full` (Sundays; scheduler re-passes `--full` if a full pass hits `--until`) sweeps all high-importance `OWNERS` with full transitive suites and compares survivors against the prior full pass. Once a pass completes with zero `unread` rows, `done.json` advances so survivors are reported once in `<commit>/report.md` rather than re-alerting unchanged lines; exit code 3 signals survivors, `unread` rows, untested changed files, or an unfinished pass. Scheduling and stack selection stay outside the repository; CI never runs it.
- **Oracle copy hygiene:** initialise `<copy>` as a git repo (`git init` + commit) when tests exercise git or `treeFault` guards; lower multi-minute `setDefaultTimeout` values on `<copy>` (e.g. `600_000` → `60_000`) so deadlocking mutants fail on the per-test timeout rather than recording `unread` at `--timeout`; size `--timeout` above each suite's loaded duration. For filesystem-mutating code, use a `cp -cRp` copy-on-write clone with retargeted symlinks/gitdirs.
