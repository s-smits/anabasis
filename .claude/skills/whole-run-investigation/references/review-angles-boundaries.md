## Boundary and repair angles

These are angles 32–36 of the same catalogue as [review-angles.md](review-angles.md).
The manifest reads both files in order. Full review includes each lane independently;
the triggers below select useful depth and govern selection only for explicit targeted work.
Use exact measured identities and existing verified joins. Report an absent opportunity or
unobservable property explicitly. Never change historical scores or controller-owned artifacts.

**32. Authoring-to-host contract compatibility.** Can a check written against the public authoring
interface execute through the real host contract? Follow one consequential request across public
types/examples, generated check, projection, tool input binding, worker transport, wall and host
result. Select a legitimate use and its nearest forbidden counterpart. Prefer an existing real-host
probe; where a new scratch probe needs authority or cannot run in this transport, give the primary
the bounded test and mark it unexecuted. A passing runtime double proves only that double's contract.

Separate a valid boundary refusing unsupported work from incompatible producer/consumer contracts
and an interface refusal whose public explanation was lost. Test the actual operand and execution
path, including lexical command identity where relevant. Do not widen private-input access, relax
the wall or forward raw verifier exceptions to make the example work. Return the first incompatible
edge, the legitimate and forbidden outcomes, exact owner, rival and smallest closing proof.
Trigger: host refusal after local success, repeated generated-evaluate failures, or a changed
authoring/host interface. Angle 1 owns what the starter teaches, Representation owns public writer
parity, 23 owns whether the rule is justified, and 34 owns the useful permitted explanation. This
lane owns whether those individually valid interfaces can actually compose.

**33. Executable verifier dependency closure.** Which bytes and runtime facts actually decided the
verdict, and could the review see them? Start from a recorded external operation and trace its
deciding dependency chain: selected command, wrapper, imports, headers, flags, linked libraries,
configuration, environment and runtime assets. Compare the host-attested inputs and executable
identity with what preprocessing and execution really consumed. Distinguish host-provided,
Builder-installed, candidate-controlled and unresolved dependencies without treating provenance
alone as independence or defect.

Read the existing source inventory's inclusion rules, delivered pages and omissions against that
chain. A complete inventory, hashed wrapper or successful compiler invocation cannot certify unseen
configuration or a substituted implementation. Conversely, an excluded file is a visibility gap
only if it can affect the deciding operation. Use a bounded contrast when it can establish that
materiality; record unavailable execution as a limit. Return the deciding chain, its unobserved or
candidate-controlled edge, the claim that edge limits, and one owner and discriminator.
Trigger: external-tool grounding, a wrapper or configuration-dependent verdict, or a reviewer claim
of full coverage. Row H owns recorded identities, 22 owns public domain facts, and 5/6 own wrong-artifact
discrimination. This lane does not repeat their tallies or presume that an installed tool is faulty.

**34. Public-safe feedback sufficiency.** Did the model-visible message retain the permitted
information needed to act? Derive the allowed public facts from the measured contract before reading
what the projection drops. Follow one consequential message from producer through typed admission
and formatting into the actual served prompt or tool return. Check the public obligation, selected
owner, blocking/advisory distinction, priority and uncertainty only where that contract permits them.

Compare two legitimately different public situations. Would the recipient see their deciding
difference? Distinguish lost public meaning, a wrong public label, deliberate protected withholding
and an inherently unobservable distinction. Reuse angle 12's confidentiality proof when available;
changing only protected detail must still leave public prompt identity unchanged. Keep private
failure locations, verifier explanations and counterexamples out of every proposed message.
Return the permitted distinction, actual rendered contrast, smallest correction at its existing
projection owner, and the behavioural effect that remains unproved. Trigger: ambiguous repeated
repair, conflicting public labels, or a changed projection/formatter. Angle 12 owns leakage, 9 owns
delivery, and 35 owns whether a later edit repaired the defect. Leak-free text alone settles none
of those other questions.

**35. Semantic repair closure.** Did the accepted successor resolve the same defect that prompted
the repair? Reuse the settled routing and delivery facts. Follow one consequential obligation and
its falsifier through finding, permitted public projection, proposal, rejected revisions, final
accepted bytes and next eligible measurement. Use the first repair and a later recurrence when
they distinguish explanations; do not recount every invocation.

Compare the final condition with the original purpose. Classify a demonstrated repair, partial
repair, neighbouring change, honest scope narrowing, removal of the challenge, recurrence or an
unmeasured outcome separately. A common check ID, changed file, consumed packet or better score
cannot establish defect continuity. If distinct defects share a public location, use that as the
nearest counterexample to an identity-only join. A deleted control may be a correction or a loss
of challenge; decide from the public obligation and realised verifier, not its deletion alone.
Report what remains unresolved, the exact owner and the observation that would reverse the result.
Keep protected repair evidence private; publish safe conclusions and pointers. Trigger: a repair
proposal or accepted successor, a repeated defect, or a claimed review benefit. Angle 9 owns routing,
34 owns message sufficiency, 24 owns memory retention and 25 owns recurrence across reviews. This
lane owns same-defect closure within the run, including a missing next measurement opportunity.

**36. Valid-alternative rejection challenge.** Can genuinely correct work fail the accepted
verifier? Work alone. Before reading verifier source, controls, recorded case verdicts or any other
oracle-challenge report, derive a bounded corpus of valid alternatives from the public task and
domain authorities. Freeze each artifact's identity, public validity argument and the property it
varies. Choose meaningful implementation diversity, equivalent representations or boundary values;
lexical difference alone does not prove validity. If this public-only derivation cannot be preserved,
record the contamination instead of claiming an independent challenge.

Then execute the frozen alternatives through the recorded public submission and verifier path
with its required wall, using authorised probes or asking the primary for the missing execution.
Separate writer/parser refusal, completed false rejection, correct acceptance and typed non-result.
Keep an ordinary valid baseline beside the alternative and identify which boundary rejects it.
Revisit the validity argument when public requirements are ambiguous; the test may be wrong.
Return the frozen corpus and exact outcomes as safe counts and evidence pointers, the owner, rival
and smallest confirming contrast. Trigger: publicly constructible tasks, a suspicious valid-source
rejection, or lexical/representation restrictions affecting a capability claim. Angles 5/6 retain
their independent plausible-wrong corpora; 19/20 judge recorded user artifacts. This lane constructs
correct alternatives and establishes false rejection. It must never share a grouped session with
another angle, and it grants no new model access or rescoring authority.
