# From v1's catalogue to v2's

v1's whole-run investigation had nine deterministic rows and thirty-eight lanes, tuned over many
runs. This file says what became of each, and what the account shows about where v2 is going. Read
it when a v1 archive names a lane this catalogue lacks, or before proposing a lane v1 already tried.

v1's catalogue is `.claude/skills/whole-run-investigation/references/review-angles.md` in
`s-smits/anabasis`, read at `3f93d06`.

Twenty-five of v1's thirty-eight lanes still have a place. The thirteen removed read machinery v2
does not have. The ten new lanes read two things v1 could not: a paired comparison, and an exam
whose author is not the Builder.

## Removed (13)

Each read something v2 does not have. A reader meeting one in a v1 archive reads it from that
archive alone.

**The Builder no longer writes the exam.**

- **3. Authoring-to-host contract compatibility.** No session authors a check, so none can be
  written to an interface the host does not serve. A check that cannot run is a fault `accept.ts`
  names (lane 3) or a refusal at gates 2 and 3 (lane 7).
- **9. Rehearsal instrument reach.** Practice runs the same verifier under the same wall as the
  round. There is no second instrument with a deadline of its own.
- **31. Brief against the request.** v2 has no request. It starts from a pack. This is the lane that
  read v1's first product, and nothing replaces it: see "Direction" below.
- **36. Difficulty pressure on the Builder.** The Builder writes no task. The question moved to the
  Examiner and changed with it: lane 12.
- **37. Battery size and probe graduation.** No sizing rule and no graduation. What a set of a given
  size can show is lane 22.

**No Judge and no Epoch Reviewer.**

- **12. Epoch Reviewer standing duties.** Nothing is authored inside a round, so nothing is reviewed
  before it. The Referee and the Diagnoser are read in lanes 29 and 30.
- **16. Judge disagreement adjudication** and **32. Judge pass decidability.** No session reads a
  pass. Lane 1 is standing for that reason and is the weaker substitute: it samples, where the Judge
  read every one.

**No controller.**

- **10. Difficulty calibration loop.** Nothing calibrates difficulty between rounds. The question
  survives in two parts: whether the tasks bracket the solver (lane 10) and whether the campaign
  climbs (lane 25).
- **17. Round hand-off census.** v1 had many channels between rounds. A v2 session is handed a
  parent harness, practice tasks, their records and the reviewers' readings, and lane 30 reads that.
- **26. Builder memory and posture.** A session carries no memory to the next. The harness state is
  the only thing that passes.

**No hardware target.**

- **29. Hardware target coverage against public ground truth** and **30. Ground-truth verdict
  comparison.** Target coverage is the pack author's. Where a check runs the field's own engine,
  `checker.read` says `external`, and lane 1 weighs it.

## Direction

The account above bears on one question: is v2 still the system v1 was, or another one.

**What v1 set out to make.** One short prompt becomes two products: an agent harness, and an
evaluation that proves the harness's failures. v1 called the second much the harder. Progress was a
climb: a fixed solver fails for a reason the evaluation can prove, a harness change answers it, the
same task passes, and the next battery asks more.

**Where v2 is the same system.**

- The yardstick. v1's public result was a harness measured at four cycles on twenty-five held-out
  tasks: 6, 8, 11 and 12 passes, against 8, 9, 8 and 8 for the comparison agent. v2 makes that shape
  its only measurement: the same tasks, two harness versions, fresh solves.
- The retired lanes. v1's catalogue had retired the paired promotion contest and the cross-harness
  baseline, with the reason that a comparison runs on one shared pack or not at all. v2's premise is
  the shared pack. Six of the ten new lanes read that comparison.
- The findings that carried. The lanes that produced v1's most consequential results are the eleven
  kept almost as written: false rejection, check mirroring, the published recipe, the trace
  challenge, the valid alternative, wall share, non-result honesty. They read properties of any
  agent set against an exam, and v2 has every one of them.
- The removals. v1 gave eight lanes and its whole stance to one difficulty: a verdict the Builder
  wrote on an exam the Builder wrote. v2 removes the difficulty and not only the lanes. That is the
  change v1's own investigations kept pointing at.

**Where v2 is a different system.**

- One product, not two. v2 takes the evaluation as an input. No session writes a check, a rule or a
  family, and lane 31, which read whether the exam asks what the request asked, has no object. For a
  domain with no pack, v2 cannot start.
- The exam does not ask more. v1's battery could grow in kind. v2's grows by instances the Examiner
  writes under fixed checks. A campaign's ceiling is its pack's, and lane 25 can report a chain of
  steps on an exam that never moved.
- Nobody owns the checker. A finding against a check is a decision for a person. v1 had an author
  for it, a poor one, inside the loop.

**The reading.** v2 is v1's harness half, made measurable, on v1's own yardstick. It is going where
v1's evidence pointed. It is narrower than v1's first sentence, by the harder of the two products,
and that cut is deliberate and should be said wherever v2 is described. Two decisions would close
the gap, and neither is made: who authors and repairs a pack, and whether an exam must ask more as a
harness improves.

**What is unproven.** The one live round so far was a plumbing run, so no comparison has yet
reported a step on a real campaign; this catalogue has read two simulated logs and two real
campaigns, both stopped before their first comparison. v1 found the
signal too rare to settle a comparison at the size it ran, 11 of 322 batteries with an uncontested
fail. v2's answer since 2026-10-09 is one compute budget for both harnesses, set where the
reference harness is valid about half the time, and first of all a measurement of how the
Starter Built Harness does by itself, read from the first round, in which a built harness is
compared with it (`docs/plan.md`, Phase 0). Whether a budget leaves enough tasks untied to show a gain is the open
empirical question, and lanes 9, 10, 22 and 23 are where it will be read.
