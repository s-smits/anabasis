# Authoring, admission and semantic comparison

Use this case when a real Builder must repair a candidate, reach admission, or be compared with
another model condition. It sits between a session segment and a full run: use the production
Builder campaign when continuation, submit, control census or full-task solvability (F2) matters.
Use a full run only when the question also needs a Built actor, measurement, promotion or routing.

## Freeze the question before opening the actor

Record the exact product revision, helper revision/digest, seed identity, original one-line prompt,
system and kickoff digests, backend/model/effort, tool roster, task count, turn and stopping bounds,
and which production stages will actually run. Separate requested pins from recorded served-model
identity; missing attestation remains unknown. A configured Built or review slot is not an executed
actor. A steward's model is not the measured Builder's model.

For several conditions, give each directly launched steward one condition and report path. Follow
the operator's model/effort choices; never use a steward as the production actor. The parent verifies
each consequential claim against its source, case rows and host evidence before comparing results.
This case specifies the experiment; it does not authorise additional model conditions or full runs.

Define the semantic discriminator before the actor sees the seed: what makes an artifact valid,
plausibly wrong, or a legitimate alternative where the public contract permits one. Agreement
between local and production results is parity; both accepting the wrong artifact fails the semantic
proof. Actual tool execution has its own host evidence. Keep predictions and probes outside
model-visible text, and preserve unresolved falsifiers after a censored ending.

When choosing a new correctness contract, test a required computation outside the motivating
domains early, under the intended tool policy. Accept a valid answer and a legitimate alternative,
and reject a material violation using the submitted artifact and public rules. If that requires an
unsupported deciding operation, reopen the contract choice before extending helpers; a status
certificate, exact reference template or domain-specific host branch does not establish expressibility.

## Make the launch match production

`scripts/run-condition.mts` is the helper for this case: it runs the real controller round over a
seeded slug (`seed-campaign.mts --as-slug`), with the Builder live under the requested pins and
the Built and review slots scripted or off, and `--builder capture` records the exact production
first prompt for that slug's epoch before anything is spent. Read the measured tree's production
composition before choosing anything else. In the 7 September
comparison, `productionBuilderRuntime` with `runBuilderCampaign` supplied the real tool mount,
continuation, submit, conformance, control census and F2. A session-only helper could not answer
admission. Those export names are historical evidence, not an API guarantee on every revision.

Carry the actual Builder system/first-prompt pair, workspace location, authoring read grant,
backend-native tools and controller tools. A `directKickoff` string alone is not the full session
contract. Capture from the real assembler where possible; record any authored replacement. Inspect
the selected parser before using flags such as `--no-tools`: a flag affecting custom tools need not
disable native tools. A missing export or grant is a setup fault, not a reluctant actor.

Keep the user's one-liner exact. A neutral seeded condition carries recorded candidate bytes and
only the memory/history its design names, without added repair hints. A correction condition uses
the real feedback belonging to those same bytes. A diagnosis from a later evaluator cannot be
attached to an earlier one. Different framing is a separate condition with its own digest.

Prepare the measured worktree once through the repository helper. For seeded candidates, copy only
the necessary bytes into an owned workspace; preserve original tests and the recorded task count.
Make the authoring copy writable where production permits it, then use the real workspace setup.
Keep a real workspace Git repository so commits cannot accidentally target its parent checkout.

Own writable toolchains as well as candidate files. Preserve relative symlinks; a recursive copy
can otherwise turn them into absolute links back to the original run. Inspect realpaths, package
resolution, compiler/data paths and out-of-tree targets. Record each necessary physical relocation
with before/after hashes. Prove a valid and hostile real-tool execution after the final copy when
those tools are the mechanism under test. Do not copy unrelated configuration or credentials to
make a launch work; use the workflow owning that configuration.

## Keep conditions comparable while they run

Within a domain, start model conditions from the same original seed and equivalent installed tool
bytes, apart from recorded physical relocations. Do not seed a later model with an earlier model's
repair. A fresh-starter comparison uses the same production starter and request; its generated tasks
will differ, so raw census totals and F2 scores are not paired solver measurements.

For a harness repair, hold tasks and evaluator fixed. For an evaluator repair or contract comparison,
replay a common compatible artifact panel with independently established expected properties through
both instruments, then establish a baseline under the new evaluator. A more accurate instrument may
lower the score. Record schema incompatibility separately; do not replace the panel with each
instrument's own references. A climb changes the difficulty condition and needs its own anchored
comparison. Judge-rated comparisons require a qualified common judge condition.

Freeze the source until its conditions close. Implement discoveries in a separate worktree. A fix
or new model condition needs a separately identified replay; an older-source result cannot become
new-source outcome proof through an ancestry claim or a passing gate.

Monitor actual milestones: last completed tool/result, settled submission, persisted gate stage,
and owned descendants. A long compiler turn is not idle because no ordinary turn has completed.
Fresh compiler children demonstrate activity, not eventual success. If the exact substage is not
saved, say unknown. Keep authorised bounds and let production continue; do not inject generic nudges
or restart an actor because another condition finished sooner.

## Probe the final bytes through the deciding host

`scripts/host-panel.mts` owns this step: one task, a known-correct accept control, small mutations
of it, through `runControls` on the real host, with the fingerprint checked before and after.
After the actor stops, bind the final workspace to its accepted snapshot or final unadmitted
candidate and hash the candidate plus relevant toolchain bytes/links. Run probes through the real
public acceptance and host-verification path on that source, with the required OS wall and actual
tools. Local generated tests, evaluator return values and fabricated tool receipts do not substitute
for the deciding consumer. Rehash after postflight; mutate probe artifacts, never the candidate.

Adapt probes to the final schema while retaining their original semantic meaning. A syntax or
old-schema rejection does not prove the intended discriminator. If a Builder removes a requirement,
record scope reduction; omission does not clear the original requirement. If original tasks are no
longer accepted, report that compatibility result separately from final-task semantics.

Check the expected result independently from public constraints. Show the small arithmetic or rule
that makes the hostile artifact wrong; repeating the generated reference answer measures agreement
with its oracle. Passing an external compiler proves compilation. It need not prove entrypoint use,
physical behaviour, mass conservation or a correct generated oracle. A valid unused helper beside
a no-op entrypoint is a useful hostile case where the public contract requires program execution.

Save each artifact, accepted/unaccepted status, verdict, failed check IDs, typed non-result, and
actual host rows with command/tool/check/case identities, digests, wall, exit and outcome. Distinguish
verified cases from unaccepted cases, non-results and unexecuted probes. A non-zero compiler exit is
a completed tool run. Selected postflight probes and separate reference-generator runs do not form
a pooled capability rate.

## Close and report the condition honestly

Keep launcher, native session, submission and execution counters separately. Acceptance can dispose
a session after one started turn and zero normally completed turns; a durable tool counter may omit
the final accepting call. Compare it with the native trace and state the discrepancy, rather than
inventing a completed turn, usage or served identity.

Prove closure of the launcher, backend, probe process and owned native children. A disposal flag,
abort call or successful signal is not evidence that the process group is absent. Scope cleanup to
identified owned processes; keep unresolved child identities, exact cells and receipts. A kernel-
stuck child can survive SIGKILL. Report it as incomplete closure and stop blind signal/retry loops;
do not erase completed case evidence or call the whole condition a semantic failure.

The report gives exact identities, production outcome and denominators, independent semantic
results, scope changes, prediction resolutions, unchanged-byte proof and process closure. Name the
failure owner: helper/setup, shared source, generated candidate or provider/host. Write findings and
their limits before implementation advice. Carry authorised source fixes through their owning tests
and delivery, then identify what remains unrun on the new source.

When the claim is improvement-loop effectiveness, continue the evidence through measured failure,
consumed diagnosis, repairing owner, changed candidate, controlled remeasurement, adoption or refusal,
and the next iteration or justified stop. Stopping at submit proves a candidate path. Missing later transitions
remain unexercised; this proof requirement does not authorise another model call or full run.

The 7 September nine-condition batch ended with six admissions, one shared reference-import refusal
and two host interruptions. Admitted truss and firmware candidates still failed independent semantic
probes. The resulting changes are described in PR #588
and PR #589 of the development repository. These are worked evidence for the
distinctions above, not default models, domain restrictions, a required nine-condition grid, or proof
that the subsequent source improves model behaviour.
