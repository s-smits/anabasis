# Mutation Testing

Mechanical mutation oracle for high-importance Anabasis owners, grounded in `AGENTS.md` (Approach 1–4, §8 rules 12–13, §9 evidence rungs, §12 test-shape hierarchy) and `tools/oxlint/HABITS.md` §12.12. Pairs syntactic mutations (`scripts/mutate.ts`) and incremental nightly sweeps (`scripts/nightly.ts`) with a simplify-first triage funnel: treat every mutation sweep equally as a **production and test simplification sweep** so bad or over-defensive production code is rewritten or deleted, low-value or unsurfaced test parts are trimmed, and only genuinely load-bearing invariants are closed through live end-to-end or space/table checks.

## How this skill connects to `AGENTS.md` and sibling skills

- **`AGENTS.md` Approach 2–3 & [`simplify`](../simplify/SKILL.md):** Fix owners structurally upstream and subtract before adding. Every non-error survivor is audited first against `simplify`'s concepts, altitude, upstream primitives, and shapes (`H1`–`H11`). Delete redundant guards, duplicate lookups, dead fallbacks, and unused flags before considering a test.
- **`AGENTS.md` §12, `tools/oxlint/HABITS.md` §12.12 & [`commit-r`](../commit-r/SKILL.md):** Follow [`commit-r/references/testing-protocol.md`](../commit-r/references/testing-protocol.md) for surface-importance triage: protect high-importance owners (measurement, Factor 1–4 folds, Rule 3 walls, `decide`/admission/stop rules, verifier/audit/sandbox/lock boundaries) and write **no** unit tests for low-importance or presentation surfaces. `commit-r` invokes this oracle at step 8 whenever amputating, shrinking, or replacing tests on a high-importance owner.
- **[`reduce-complexity`](../reduce-complexity/SKILL.md):** Measure before/after complexity (`git complexity`, branching density, import coupling) when simplifying production code or splitting presentation prose out of decision owners.
- **[`promotion-tuner`](../promotion-tuner/SKILL.md) (`AGENTS.md` Approach 4):** Replay rule/guard changes over `data/runs/` and inspect callers before deleting a surviving guard to confirm reachability and zero false positives.
- **[`system-path-simulation`](../system-path-simulation/SKILL.md):** Syntactic mutants catch boundary and logic gaps, never omitted requirements or cross-file semantic drift. Pair mutation sweeps with model-free rehearsals, replays, and Rule 3 perturbation walls.
- **[`repository-practice`](../repository-practice/SKILL.md) & [`local-checks`](../local-checks/SKILL.md):** Report findings using §9 exact denominators and evidence rungs (`proved without a model`, not "done"). Sweeps run locally and on the fleet, never in GitHub Actions.

## Commands

```sh
bun .claude/skills/mutation-testing/scripts/mutate.ts list <copy> <files...>
bun .claude/skills/mutation-testing/scripts/mutate.ts run <copy> <files...> --out <scratch>/kills.jsonl --suites <suites.json> [--fleet] --stop-at-kill --timeout 120
bun .claude/skills/mutation-testing/scripts/mutate.ts report <scratch>/kills.jsonl [--old old] [--survivors]
bun .claude/skills/mutation-testing/scripts/nightly.ts <tree> --state <dir> [--until HH:MM] [--timeout s] [--diff <base>] [--full]
```

## Four-stage survivor triage funnel (nightly & hardening passes)

Never chase raw survivor counts with isolated unit tests or synthetic event snippets. Work in order, drawing on `AGENTS.md` §12 and industrial mutation practice (Petrović & Ivanković / Google ICSE 2018 & TSE 2021; Meta ACH FSE 2025; Just et al. FSE 2014):

1. **Verify suite coverage first (separate measurement artefacts from real gaps).**
   `nightly.ts` selects tests via `tools/runtime/gate.ts`'s `within` primitive (full runtime-transitive imports in every mode, direct importers first, dropping `import type` and `export type` edges; coverage pruning keeps suites that never execute a mutated line from running) plus non-import string-literal path mentions, ordered fastest-first by `test/.test-timings.json` (then file size) and executed as one bailing `bun test --bail` batch per mutant. When triaging an older pass whose suite list missed transitive importers, confirm survivors against the missed suites first (`--only <ids> --stop-at-kill`) before editing code or tests. Prioritise **diff-scoped / new survivors** (`report.md` against `done.json`, or `git diff --name-only <base> -- src tools`) over historical sweeps to keep signal high.
2. **Cluster confirmed survivors by subsuming invariant — audit production design and test value before adding tests.**
   Inspect each surviving expression inside its full enclosing function, callers, and existing suites (Meta ACH showed deterministic context pre-processing lifts equivalent-mutant filtering from 0.79/0.47 to 0.95/0.96 precision/recall). Treat every survivor as a dual diagnostic before touching any test:
   - *First ask: "Is the production implementation itself bad, redundant, or over-engineered?"* Often a surviving branch signals an awkward implementation that should be rewritten cleanly or deleted (`AGENTS.md` Approach 2–3, §8 rules 12–13) — for example, carrying a value directly instead of re-looking it up by index, deleting a sort or tracking field that zero callers observe, nesting a shared precondition instead of repeating guards, or dropping a single-caller wrapper. A better production shape eliminates whole survivor clusters by deletion.
   - *Second ask: "If no existing test surfaced this, is the behaviour—or the surrounding test—even earning its keep?"* Never assume a survivor automatically deserves a new test. When inspecting a suite reveals duplicated cases, synthetic snippet tests that miss the real flow, or narrow assertions on incidental details, trim or consolidate those weak test parts (using `commit-r` step 8 on high-importance owners) rather than piling more tests on top.
   Classify each cluster strictly in order:
   - **Live defect or inert test:** production code is wrong today, or an existing test's fixture accidentally short-circuits before reaching the branch it claims to pin (for example, failing an earlier validation gate). Fix the owning module structurally upstream (`AGENTS.md` Approach 2) or fix/prune the inert fixture directly rather than adding a second test.
   - **Bad, unneeded, or over-defensive production surface:** dead guard, unused sorting/tracking field, duplicate lookup/loop, unreachable fallback, redundant flag, awkward control flow, or incidental branch no caller relies on. Delete or simplify the production code via [`simplify`](../simplify/SKILL.md) (or [`commit-r`](../commit-r/SKILL.md) for a compartment rewrite, checking [`promotion-tuner`](../promotion-tuner/SKILL.md) archive reachability where a rule changes) rather than writing a test to defend code that should not exist.
   - **Unpinned high-importance invariant:** truly load-bearing logic on measurement, Factor 1–4 folds, Rule 3 walls, `decide`/admission/stop rules, security/path boundaries, or refusals. Close the **subsuming invariant** for the whole cluster following `AGENTS.md` §12 and [`commit-r/references/testing-protocol.md`](../commit-r/references/testing-protocol.md) in order:
     1. **Space, property, wall, and table checks (`AGENTS.md` §12 ranks 1–3):** bounded exhaustive checks against an independent rule (`≤~10s`), state-space search over reachable logs, seeded LCG generators, shared perturbation walls, or pure invariant/view-model tables.
     2. **Boundary and integration checks through live end-to-end flows (`AGENTS.md` §12 rank 4):** for process/file/provider/OS-wall boundaries, nearest hostile refusals, or real-run regressions, fold the case into an existing live lifecycle entry point (`harnessBuilder`, `examine`, `revisionRunner`, `openSuccessor`, `freezeCandidate`, `runs` commands) by adjusting a real fixture input or step rather than adding isolated helper calls, synthetic event snippets, or fake stubs.
     3. **Narrow unit tests only as a last resort:** only where neither space/table checks nor live end-to-end entry points can feasibly reach the boundary. Never add module mocks, fixed sleeps, or test-only exports (`HABITS.md` §12.12).
   - **Arid, low-importance, or presentation surface:** logging calls (suppressed in `mutate.ts`), CLI wording, formatting, advisory notes, or incidental low-value branches. Write **no** test ([`commit-r/references/testing-protocol.md`](../commit-r/references/testing-protocol.md)); answer it as `presentation` in the ledger below.
   - **Proved equivalent mutant:** identical observable behaviour on all reachable inputs. Write **no** test; answer it as `equivalent` with the one-line proof.

   **Answered survivors** live in `answered-survivors.tsv` beside this file, one tab-separated row per answer with columns `path`, `label`, `source`, `kind`, `reason` (the trimmed source line, as the report prints it; kind `equivalent` or `presentation`; a reason a reviewer can check). `nightly.ts` drops answered survivors from the report and exit code, refuses a row without a kind or reason, and lists rows a `--full` pass no longer finds as stale. An edit to the line retires its answer, so a changed line is triaged again. Code no test reaches is not answerable: delete it, make its state unrepresentable, or reach it through a live entry point. Common deterministic equivalence classes:
     - strict vs non-strict comparison (`<` vs `<=`, `>` vs `>=`) between distinct log event kinds that can never share an index;
     - negative-sentinel shifts (`-1 -> -2`) compared against non-negative array or log indices;
     - redundant defensive guards already guaranteed by an earlier invariant or callee (`isContextOverflow`, empty-set no-ops, unreachable `null` fallbacks — prefer deleting via `simplify` if clean);
     - algebraic/monotonicity equivalences (verify with a quick bounded script when non-obvious).
3. **Prove every kill against the oracle (zero inert tests).**
   Run `mutate.ts run --only <target-ids> --stop-at-kill` against the edited suites (`ANA_CHECK_HOST=here --jobs N` locally for fast targeted checks; `nightly.ts` writes `survivors.diff-<base>.ids.txt` / `survivors.ids.txt` beside `report.md` and clusters survivors by `file:line` sorted by density). Verify **per targeted line** that every intended mutant flips from `survived` to `killed` with zero `unread` rows: a mutant still surviving on a line you edited a test for proves the test is inert (fix the fixture so it reaches the branch, or delete the test). Then run `bun fmt`, `bun run typecheck`, `bun run lint -- --strict`, `bun tools/loc/source-policy.ts`, and `bun run simplify -- --gate` ([`repository-practice`](../repository-practice/SKILL.md)).
4. **Track yield and respect oracle limits (`AGENTS.md` §9).**
   Report exact denominators in the commit/PR: survivors read, indirect kills removed, live defects fixed, production simplifications/deletions landed, real invariant gaps closed (noting end-to-end vs space/table vs boundary), equivalents retired, and simplification leads queued. Pair with [`system-path-simulation`](../system-path-simulation/SKILL.md), Rule 3 perturbation walls, and [`promotion-tuner`](../promotion-tuner/SKILL.md) replays to cover semantic properties beyond first-order syntactic mutants.

## Routing non-error survivors to `simplify`, `commit-r`, and `reduce-complexity`

A surviving mutant that is **not** a bug and **not** worth a new test is often a structural simplification signal (`AGENTS.md` Approach 3, §8 rule 13). Before retiring a non-error cluster, check whether deleting or restructuring production code beats leaving it behind:

| Non-error survivor pattern | What it signals | Route to |
| --- | --- | --- |
| Redundant defensive guard (`A \|\| B` where `B` already holds whenever `A` holds, or callee already checks `A`) | Unneeded branch or double validation across a seam (`simplify` H1–H11) | [`simplify`](../simplify/SKILL.md) (delete redundant guard; make invariant unrepresentable) |
| Unused ordering, tracking field, or awkward re-lookup (`toSorted` whose callers only call `.get`/`.has`, index re-lookup after finding a record) | Bad or over-engineered production shape | [`simplify`](../simplify/SKILL.md) / [`commit-r`](../commit-r/SKILL.md) (delete unused work; carry the needed data directly) |
| Unreachable fallback (`?? default` that never triggers on reachable states) | Dead code or over-wide return type | [`simplify`](../simplify/SKILL.md) (narrow type, remove dead fallback) |
| High arid-mutant density inside a high-importance owner (prose, advisory notes, CLI formatting mixed into decision folds) | Presentation entangled with decision logic | [`commit-r`](../commit-r/SKILL.md) / [`reduce-complexity`](../reduce-complexity/SKILL.md) (split pure decision fold from presentation surface so high-importance owners stay small and high-signal) |
| Low-value or unsurfaced test coverage (narrow synthetic unit tests that miss real flows or duplicate existing suites) | Bloated test surface obscuring real invariants | Trim or consolidate weak test parts ([`commit-r`](../commit-r/SKILL.md) step 8 on high-importance owners); prefer one space/table or live-flow check |
| Surviving `swap rows` in a decision table | Either an unpinned precedence invariant or disjoint rows with hidden coupling | Inspect reachability via [`promotion-tuner`](../promotion-tuner/SKILL.md) / callers first; pin precedence if order matters, else simplify |

Never delete a guard solely to raise kill rate — verify reachability across `data/runs/` and callers first (`AGENTS.md` §9, §12). Record confirmed simplification leads alongside retired equivalents so subsequent [`simplify`](../simplify/SKILL.md) or [`commit-r`](../commit-r/SKILL.md) passes pick them up cleanly.

## Rewrite-time oracle (`commit-r` step 8)

When deleting, shrinking, or replacing tests on a high-importance owner in [`commit-r`](../commit-r/SKILL.md):

- **Comparative mode (`--old`, Test pass or interface-preserving Rewrite):** run `old`, `new`, and `kept` suites on `<copy>` with old tests restored. Classify every `O-` survivor as either a genuine invariant/boundary gap (close with a bounded/property check; never paste back old example boilerplate) or intentionally retired incidental wording/convenience (record in the commit message). **Leaving >15% of `O-` survivors unexplained or any `unread` row halts the pass** (`report --survivors` prints unread IDs after survivors for `--only` reruns).
- **Solo mode (interface-changing Rewrite):** never mix incompatible `old` and `new` suites on one copy. Run `mutate.ts` against `new` + `kept` (`report` without `--old`), inspect `--survivors`, and close surviving decision, wall, or refusal branches.
- **Skip** on pure low-importance amputations; verify surviving boundary tests, `bun run gate`, and real-input oracle/replay instead.

## Mutation rot (high to low risk)

Mutants rot as code, callers, and test fixtures evolve. Check rot risk in order before trusting a zero-survivor result:

- **High — moved code & stale `--only` IDs:** mutant IDs encode `<file>:<byteOffset>:<label>`. Any edit above a recorded survivor shifts byte offsets so saved `survivors*.ids.txt` entries silently match nothing (`mutate.ts` prints a `stale --only IDs` warning on `stderr` when requested IDs miss). Never treat `0 mutants run` on a stale ID list as proof a fix worked—re-run against the current tree and confirm each targeted line flips from `survived` to `killed`.
- **Medium — fixture-blind tests & stale diff baselines:** a test whose fixture omits a relevant input variant (or only exercises a happy path) leaves mutants alive on lines that appear covered, and incremental diff-hunk runs do not re-test unchanged lines when a callee or shared fixture changes. Re-run the whole touched owner (or `--full`) after refactors or fixture rewrites.
- **Medium — rows recorded under an older suite list:** a resumed pass skips every mutant that already has a row, whatever suites ran it, so survivors recorded before a suite-selection change are never re-tested. Drop only the survivor rows from the state's `<slug>*.jsonl` (kills stay valid, since more suites cannot un-kill a mutant) and resume.
- **Low — retired equivalents & arid blocks:** a mutant proved equivalent under an earlier invariant can become observable once that invariant is relaxed; revisit retired equivalents whenever the enclosing owner changes.

## Execution & clone hygiene

- **Host routing & two-stage execution:** `mutate.ts` pairs **Mode-1 In-Process Mutant Schemata** (`mutate-schema.ts`) with a **Mode-2 Unified Fleet Process Pool** (`mutate-pool.ts`, `mutate-exec.ts`, `tools/runs/host-config.ts`). Under `--prune --stop-at-kill` when local execution is available, Mode 1 compiles function-body mutants (excluding chained short-circuit precedence swaps and top-level initialisers) into one in-memory `Bun.plugin` meta-mutant per file, probes pure deterministic suites once in parallel (aborting automatically if the target executes at import time or fails baseline) to capture exact per-`it()` reachability and durations, ranks pure suites by `coveredMutants / baselineMs`, and shards mutants across local cores running only covering `it()` tests fastest-first with a per-mutant watchdog and baseline self-verification on every kill. Remaining undecided mutants and impure/subprocess suites flow into Mode 2 (`checkPlaces` / `fleetPlaces`, `--local <cores>`, `--batch 48` via `mutate-batch.ts`, `--cov-cache`): LCOV (`DA:<line>,0`) runs only on needed non-subprocess suites, local slots pull one mutant at a time at adaptive concurrency (`min(2, cores / (2 × busy slots))`) using parallel APFS copy-on-write clones and symlinked `node_modules`, and each remote slot runs `min(6, cores / (2 × slots))` isolated lanes, so a host's slots together use about half its cores (each lane keeps the synced root pristine, copying `src/`, `tools/`, `test/`, `.claude/`, `studies/`, and mutant/suite roots via `cp -cRp` on macOS or `cp -al` hardlinks on Linux while symlinking `node_modules`, `.git`, `packages/`, and other untouched directories), streaming rows back line-by-line while local workers tail-hedge lagging remote mutants. Under `--stop-at-kill`, `nightly.ts` leads with direct 1-hop importers ahead of transitive suites, Mode 2 dynamically ranks active suites by LCOV hit-density + Bayesian kills-per-second, runs the lead suite solo then distinct single-file rest suites in one bailing `bun test --bail` process (re-verifying any combined kill solo and falling back individually on cross-file leakage or timeouts), and bounds hangs per suite (`min(--timeout, max(20 s, 12× baseline + 10 s))`), keeping Bun's per-test `--timeout` past that wall (`testWallMs`) so a stalled test under load ends the run as `null` and never reads as a kill (`unread` whenever no suite kills the mutant). Every active suite must pass unmutated on each host before mutating there; a place giving no verdict hands its remaining mutants back and takes no more. Unrun mutants stay unrecorded so rerunning the same command resumes cleanly.
- **Incremental diff-hunk nightly mode & weekly full sweep:** after an initial complete `OWNERS` pass writes `done.json`, `nightly.ts` defaults to **diff-hunk mode** (`git diff --unified=0` via `changedLinesInDiff` in `src/meta/git.ts`): it mutates only mutants whose start line falls on a changed line across every modified production file under `src/` and `tools/` since the previous complete pass (falling back to `merge-base(origin/main, HEAD)` when the stored commit is no longer an ancestor after a rebase or new stack, or using `--diff <base>` verbatim; pure-deletion hunks produce no mutants), writing `<slug>.diff-<base>.jsonl` with the same transitive suite selection as `--full`. `--full` (Sundays; scheduler re-passes `--full` if a full pass hits `--until`) sweeps all high-importance `OWNERS` with full transitive suites and compares survivors against the prior full pass. Once a pass completes with zero `unread` rows, `done.json` advances so survivors are reported once in `<commit>/report.md` rather than re-alerting unchanged lines; exit code 3 signals survivors, `unread` rows, untested changed files, or an unfinished pass. Scheduling and stack selection stay outside the repository; CI never runs it.
- **Oracle copy hygiene:** initialise `<copy>` as a git repo (`git init` + commit) when tests exercise git or `treeFault` guards; size `--timeout` above each suite's loaded duration, since a hang records `unread`, never a kill. For filesystem-mutating code, use a `cp -cRp` copy-on-write clone with retargeted symlinks/gitdirs.
