# Cycle ledger template

`cycle.md` records evidence against each step of [the release cycle](../SKILL.md#the-release-cycle), which owns their ordering and authority; this template grants none. It resides alongside each run's ledgers ([the cycle's files](../SKILL.md#the-cycles-files)).

**Authority and scope**: record the operator's exact authorisation with a link to its source; the named runs, commits, hosts, promotion threshold, and any `--keep` exceptions; the authority governing stops, patches, landing, and release; and all open decisions.

**Evidence**, one line per item:

- progress: step, state, timestamp with UTC offset read from the system clock when written (`date -u`, rather than an expected completion time), and the evidence path or exit code;
- stops: closed runs compared against named runs, listing exceptions and unread runs separately;
- investigation: each investigation directory (containing `iteration.json`), synthesis, `vetting.md`, `cross-domain.md`, and `deviations.md`;
- plan: each `plan.md` with its `Pull request: #N`, verification checks, and exit codes;
- predictions: the cycle view generated by `wri2p2.ts ledger <cycle folder>`, which is derived on demand and never copied into this file;
- release: the operator's authorisation, tree-equality proof, land result, merge commit, and release tag;
- next cycle: its ledger path, authority, runs, and commits.

**Timers**: list each armed timer (name, id, schedule with UTC offset, creation date, purpose, and authority) using the format in [timers.md](timers.md). Record one row for each firing that produced a state change (system clock timestamp, what changed, predictions resolved, and timer updates), and omit firings that found nothing to do. Note which session holds any step that multiple sessions could claim, and append a dated line for work performed between firings. Convert any local-time log entries to UTC when quoting them, and note the conversion in the row.

**Loop diagnostics**, recorded at each handover: the output of `timers.ts` over the session's transcripts (total, active, and quiet firings per timer); for each iteration closed during the cycle, the elapsed hours from its trigger event to its fork's `campaign.opened` event; the predictions written for a fix compared against those that held in the subsequent fresh run; and the `measures` lines from `wri2p2.ts due`, indicating which modified files no live run currently exercises.
