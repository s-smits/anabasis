Read this to decide whether code or a model owns a decision, especially before adding a limit,
classifier or file-access rule. It gives the reasons behind `AGENTS.md` section 2.

## 2. The stance: code owns the conditions, models own the content

Code keeps a decision when a model cannot observe its facts, when the model is itself the subject,
or when the value must be identical on both sides of a comparison. Models keep the rest because code
cannot reason about a domain it has never seen. The consequences, with what each rests on:

1. **Facts, never a course.** A model told what to do follows the instruction instead of the
   evidence.
2. **Facts instead of a target.** An author told a zone or a count writes towards it, and one told
   each answer's distance from a limit moves the limits. The Examiner therefore hears what the
   reference side measured and the solve budget (section 3, "What the Examiner reads").
3. **The Builder is free.** Its one limit is that no part of a harness names a task, copies its text
   or holds its answer; a program may search candidates against the public rules, and the solver
   still writes and submits the answer (`src/builder/prompt.ts`). One budget prices whatever a
   harness does, so a second limit adds nothing.
4. **No classifier in code.** Code may validate a declared structure; code deciding what a harness
   or task should contain is a model's decision made badly.
5. **Conditions stay with code.** The Builder may request a move and code decides whether it starts.
   Where a model's output feeds a decision, as a ruling does, code states the evidence it must carry
   and refuses it otherwise.
6. **Allow the whole.** The wall protects hidden values, credentials and each seat's files. Reads
   are open with protected roots closed by name, and each seat writes one root whole, the host's own
   folder inside it excepted (`SolveDirs`, `src/tools/command.ts`). Every narrower grant is one more
   policy to keep true on two operating systems; on the record narrow grants ended solves by the
   dozen while no wide one leaked a hidden value (`7f0add79:docs/plan.md`, rows B10, B12, B17).
   Narrow only where two grants collide, such as two solves writing one path in a shared `/tmp`.
   Each policy is checked by a wall test once per process (`walledBase`, `probeWall`).
7. **The simple path.** Each mechanism makes the next change harder to read, prove and undo, so a
   plain mechanism whose events can be counted beats a complete one nobody can check (rule 13). A
   false step costs more than the code saved, hence the exception for rules 3 to 8.
